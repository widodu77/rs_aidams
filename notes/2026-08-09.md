## The fixed-policy frontier

500 items per policy, 100 per category, Qwen3-1.7B 4-bit NF4, greedy, cap 768.

| category | never acc | always acc | never tok | always tok |
|---|---|---|---|---|
| `simple_python` | 88.0% | **95.0%** | 35.1 | 176.9 |
| `multiple` | **93.0%** | 86.0% | 35.5 | 204.7 |
| `parallel` | 18.0% | **67.0%** | 46.4 | 236.5 |
| `parallel_multiple` | 29.0% | **70.0%** | 57.0 | 362.3 |
| `irrelevance` | 31.0% | **81.0%** | 27.1 | 254.2 |
| **OVERALL** | 51.8% | **79.8%** | 40.2 | 246.9 |

Reasoning buys +28.0 points overall for 6.1× the tokens.

**Neither policy dominates, and the exception survived the full sample.** On `multiple` — one call, several candidate functions — not thinking is better, 93.0% against 86.0%. This was visible at n=41 (93.0 vs 82.9) and held at n=100 (93.0 vs 86.0); the gap narrowed but did not close or reverse. That single row is the empirical case for the project: a fixed policy is leaving accuracy on the table in both directions, so a per-call gate has something real to capture. It is not an artefact of the small partial run.

The largest gains are where reasoning has actual work to do — decomposing a request into several calls (`parallel` +49, `parallel_multiple` +41) and deciding that no function applies (`irrelevance` +50). `never` scores 31% on irrelevance: without reasoning the model simply calls something.

Diagnostics are clean. Truncation ≤5% everywhere (worst on `always/irrelevance`), so the cap is not driving the accuracy numbers. `never` think-rate is exactly 0.0% across all 500 items, so that policy is perfectly enforced.

## Finding: the base model already gates, and gates badly on hard items

`always` think-rate is **not** 1.0 — it is 84.6%, and it varies sharply by category (`multiple` 97%, `irrelevance` 95%, `parallel_multiple` 85%, `simple_python` 82%, `parallel` 64%). The cause is not a prompting failure: with `enable_thinking=True` Qwen3 opens `<think>` and immediately closes it, emitting `<think>\n</think>` and going straight to the call. It declines to reason.

Splitting the `always` run by whether the model actually reasoned:

| category | self-gated n | gated acc | reasoned n | reasoned acc |
|---|---|---|---|---|
| `simple_python` | 18 | 94.4% | 82 | 95.1% |
| `multiple` | 3 | 66.7% | 97 | 86.6% |
| `parallel` | 36 | 47.2% | 64 | 78.1% |
| `parallel_multiple` | 15 | 46.7% | 85 | 74.1% |
| `irrelevance` | 5 | 80.0% | 95 | 81.1% |
| **all** | 77 | 61.0% | 423 | 83.2% |

On `simple_python` the gate is well calibrated — gated items score 94.4% against 95.1% for reasoned ones, i.e. it skipped reasoning exactly where reasoning was not buying anything. On those 18 items, 13 produced a call byte-identical to the `never` run's.

On `parallel` and `parallel_multiple` it is not: gated items score ~47% against ~78%/74% for reasoned ones. **The base model's gate fires hardest on the category where reasoning helps most** (`parallel`, +49 points), skipping it on more than a third of items.

**This is an observation, not yet a causal claim, and the confound must stay visible.** The model chooses which items to gate, so gated items are a self-selected set and may simply be harder. What the table shows is that the gate is *not* selecting easy items on the parallel categories, which is what a well-calibrated gate would do — and demonstrably does do on `simple_python`. It does not show what those 36 items would have scored had the model been forced to reason.

The counterfactual is cheap to obtain (77 items) and would convert this into a result: force reasoning on exactly the gated items and see whether accuracy recovers toward the reasoned-item rate. Noted as the next experiment.

Two consequences either way:

1. **The `always` anchor is not a true upper bound.** It is "always, except on the 15.4% the model declines", and the exclusions are concentrated in the parallel categories. Every reported `always` number carries this caveat and the writeup must state it rather than presenting a clean fixed-policy baseline.
2. **It raises the bar the learned gate has to clear.** The comparison is no longer "learned gate vs no gate" but "learned gate vs the crude one Qwen3 already has". That is a harder and more honest test, and the miscalibration on `parallel` is where the headroom is.

## Phase C — reward function

`src/rewards/reward.py`, with `tests/test_reward.py`. Suite now 49 tests (29 scorer, 20 reward), all passing.

```
reward = w_correct * correct + w_format * format_ok - lambda_think * min(think_tokens / budget, 1)
```

Three decisions that are not obvious and are worth defending:

**Only think tokens are priced, never completion length.** Penalising total length would charge the model for the tool call itself, and call length is a property of the category — `parallel_multiple` needs several call blocks by construction. Pricing completion length would convert a category effect into an apparent reasoning effect, exactly the confound this project has to avoid. Pinned by a test.

**The penalty is normalised by a token budget, not charged per raw token.** With raw counts `lambda_think` has to be ~1e-3 to be commensurate with a correctness of 1.0, and its meaning changes silently whenever the generation cap changes. Normalising makes the cost bounded in `[0, lambda_think]`, so lambda reads directly as "the most thinking can ever cost, in units of one correct call" — which is the quantity the Phase E curve is parameterised by. Clipped at the budget so an over-long generation, which already scores zero correctness for never reaching the call, is not punished twice.

**`w_format = 0.2`, not 1.0.** This one nearly became a bug. `format_ok` means "nothing malformed was emitted" and is therefore True for prose containing no tool call at all — deliberately, from the Phase A split. At a weight near correctness that makes silence competitive: the model collects most of the reward by never risking a call. At 0.2 it stays a tie-breaker between two genuine attempts. Pinned by a test asserting that well-formed prose scores below a correct call.

An empty `<think></think>` is charged zero and does not count as reasoning, following directly from the self-gating finding — the empty block is the model declining to reason, so charging it would price a decision it did not make.

The reward is deliberately not category-aware beyond what `score_sample` already does. No hand-written rule about when reasoning is appropriate may enter the reward, because that is the thing being learned. The reward states what thinking costs; whether it was worth paying is settled by whether correctness rose.

`make_reward_fn` adapts this to TRL's `fn(prompts, completions, **columns) -> list[float]` signature, tested explicitly — a shape mismatch there surfaces as an opaque trainer error many minutes into a GPU run. `compute_reward` returns every component separately, because a policy that collapsed to never-think and one that started emitting malformed calls both flatten the reward curve and only the component traces distinguish them.
