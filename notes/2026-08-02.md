# 2026-08-02 — Phase A: per-sample BFCL scoring

## Goal

Establish whether a single model output can be scored programmatically in isolation. Everything downstream depends on this: the evaluator *is* the GRPO reward function, so no training is possible until `score(prediction, ground_truth) -> float` exists.

## Findings

**The anticipated obstacle was wrong.** I expected BFCL's checker to be batch-CLI-only and to need reimplementing for per-sample use. It isn't: `ast_checker()` already takes a single prediction and returns `{"valid", "error", "error_type"}`. This is a meaningful de-risking — the official checker can serve as the reward directly, so reported numbers stay leaderboard-comparable.

**Friction 1 — import coupling.** Importing the checker triggers:

```
ast_checker → MODEL_CONFIG_MAPPING → every API model handler → qwen_agent → soundfile
```

A missing audio library blocks a pure-string AST checker. The whole chain resolves exactly one boolean, `underscore_to_dot`, which rewrites `.` → `_` in function names for providers (OpenAI, Mistral, Google) whose APIs reject dots. Worked around by pinning `CHECKER_MODEL_NAME = "gorilla-openfunctions-v2"` (flag is False → names compared verbatim). **Risk noted:** this fragile chain has to survive the Colab environment too.

**Friction 2 — decode is the real work.** The checker expects `{"func_name": {arg: value}}`; the model emits `{"name": ..., "arguments": {...}}`. The shape conversion plus `<think>` separation is what actually had to be written.

**Data schema.** Ground truth is `{func_name: {param: [acceptable_values...]}}` — a list of acceptable values per parameter, where `""` marks the parameter optional. So BFCL already permits multiple valid answers per item.

**Design point that nearly became a bug.** `format_ok` initially conflated "emitted malformed JSON" with "emitted no call at all". These must stay separate: on irrelevance items, zero calls is the *correct* answer. Whether "no call" is right or wrong is category-dependent and belongs to the scorer, not the parser. Split into `format_ok` (nothing malformed) and `has_calls`.

## Verification

Scorer discriminates correctly across: correct call (with and without reasoning), wrong argument value, wrong function name, missing required parameter, hallucinated parameter, wrong argument type, wrong call count, malformed JSON, prose-only output, correct abstention on irrelevance, and spurious call on irrelevance.

Also noted: `ast_checker` leaves a stale `error_type` populated even when `valid=True` — never branch on `error_type` without checking `valid` first.
